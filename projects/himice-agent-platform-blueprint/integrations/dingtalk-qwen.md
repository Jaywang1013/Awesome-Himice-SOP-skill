# 千问与钉钉接入判断

## 结论

公司取得千问办公月度会员，对推广 AI 办公和降低员工使用门槛有利；但不能仅凭“会员”认定已经打通钉钉或取得生产 API 权限。

必须区分三个授权面：

| 授权面 | 解决什么 | 不能替代什么 |
| --- | --- | --- |
| 千问办公会员/席位 | 员工在官方产品内交互使用模型和办公能力 | 不自动提供钉钉机器人、组织数据权限或生产 API |
| 阿里云百炼模型/API 套餐 | 后端、Agent 或指定工具调用千问模型 | 不自动取得钉钉组织、审批、文档和消息权限 |
| 钉钉开放平台/企业应用 | 机器人、消息、文档、待办、审批、通讯录等企业能力 | 不自动包含千问模型调用额度 |

因此，千问可以成为 Himice Skills 的第四种运行时或模型提供方，钉钉可以成为统一入口；二者通过企业应用、机器人、CLI/MCP 或后端适配器连接，而不是依靠会员自动互通。

## 推荐接入方式

### A. 首选：DingTalk Workspace CLI + 本地 Skills

[DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli) 是钉钉面向人和 Agent 的官方开源 CLI，提供结构化输出、内置 Agent Skills、OAuth、权限范围和钉钉产品命令。其机器人快速入门支持把 Codex、Claude Code 等本地命令接到钉钉群，也支持用自定义一次性命令接其他运行时。

适合当前项目，因为现有 Skills 无需迁移到云端：钉钉只负责收发，实际文件仍可在获授权的本地机器处理。

### B. 企业机器人 Stream 模式

需要稳定双向消息、图片、附件或卡片时，创建钉钉企业内部应用并启用机器人 Stream 模式。Stream SDK 负责接收消息和回调，适配器负责调用 Himice Skill。

与现有 `dsh-dingtalk` 的区别：Webhook 通知适合“Agent 主动发消息”，Stream 企业机器人适合“员工在钉钉里发起任务并持续交互”。

### C. 千问作为模型/运行时

只有在合作权益明确覆盖时启用：

- 若仅包含千问办公会员：用于员工在千问产品内交互办公，不用于共享后端机器人。
- 若包含面向 Agent 工具的个人套餐：遵守单人、交互式使用和禁止生产自动化等限制，不共享 API Key。
- 若包含团队/企业 API 或百炼生产调用：为每个业务空间配置最小权限和成本上限，再接入钉钉机器人。

## 向阿里/钉钉客户经理确认的清单

在试点前取得书面或控制台可验证答案：

1. 具体产品 SKU、会员名称、席位数和使用主体是什么？
2. 是否包含 API Key、模型额度或百炼业务空间？允许交互式工具还是生产自动化？
3. 是否包含钉钉 AI 助理/企业机器人/开放平台应用权限？
4. 公司管理员能否启用 DingTalk Workspace CLI，并限制到指定部门、用户和数据范围？
5. 输入文件、提示词和输出是否用于模型优化？能否关闭？存储地域和保留期限是什么？
6. 是否支持公司级审计、RBAC、用量统计、离职回收和密钥轮换？
7. Office 文件、图片、PDF、录音的上传限制和数据处理条款是什么？
8. 钉钉文档、网盘、会议纪要、待办、审批、宜搭分别需要哪些接口权限？

## 试点范围

建议先选择 3—5 名同事、一个测试群和非真实客户数据：

1. 验证千问办公会员能否直接发现或调用本地 Skill。
2. 验证 `dws auth login` 和只读钉钉命令是否得到管理员授权。
3. 建立测试机器人，只允许白名单用户/群。
4. 运行一个不含税号、发票和录音的预算样例。
5. 再测试附件回传和人工确认；最后才测试待办或审批草稿。

试点通过后再决定是继续本地运行，还是采购企业 API 并部署集中服务。

## 计费与合规提醒

阿里云百炼的通用模型 API 默认按调用计费；个人或特定订阅计划可能限制为单人交互式工具使用，禁止共享或作为生产自动化后端。不得把某位员工的会员/API Key 配置为全公司钉钉机器人的公共密钥。以公司合作合同、控制台权益和当期官方条款为最终依据。
