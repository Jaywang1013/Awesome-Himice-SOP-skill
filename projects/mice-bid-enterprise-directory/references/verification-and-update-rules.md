# 招投标检索、核验与更新规则

## 候选池形成

1. 把用户需求拆成地点、服务半径、活动类型、产业链环节、服务范围、规模、必备资格和排除条件。
2. 先按 `country`、`region`、`province`、`city`、`unit_type`、`industry_chain_position`、`tags`、`service_scope` 做可解释筛选；名称关键词只能作为补充，不能作为唯一依据。
3. 在每个候选记录中保留 `company_id`、名称、匹配理由、`trust_level`、`confidence`、`verification_status`、`data_source_summary`、`updated_at` 和待复核项。
4. 目录结果只能称为“候选池”或“公开信息线索”。招标人最终资格、价格、履约能力、排他性、征信、合规和利益冲突，均须按照招标文件与公司制度单独核验。

## 排序原则

- 优先匹配明确的招标条件，再使用地域、产业链和服务范围缩小范围。
- `trust_level`、`confidence`、更新时间和来源丰富度只能作为复核优先级，不得自动形成供应商评分或中标建议。
- 有“待外部核验”“待主体核验”“待补充”表述的记录，输出时必须显著标明待办。
- 不因电话、邮箱、地址缺失而降低企业资格；也不因名录出现而视为已准入。

## 人工核验与增量更新

至少按项目需要回查企业官网、招标文件指定平台、主管部门/权威协会公告、场馆或酒店官方信息，以及供应商提交的盖章材料。记录核验日期、核验人、URL/文件来源、结论和未解决项。

保留原始 CSV 不直接改写；新增/修订应在独立的受控增量表中记录 `company_id`、字段名、旧值、新值、来源、核验日期、经办人和审核状态。发布新基线时记录行数、字段变更、校验和、抽样核验结果和回滚文件。
