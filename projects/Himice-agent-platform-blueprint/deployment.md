# 部署路线

## 阶段 0：现状基线

- 三套 Himice Skills 按仓库 README 部署到同事电脑。
- 敏感原件与输出保存在本地任务目录。
- 使用现有 `dsh-dingtalk` / `dsh-notifier` 发送完成、失败和等待确认通知。
- 通知机器人只能出站推送，不把它当成完整双向 Agent。

验收：同一测试用例在三个运行时生成结果一致；模板、金额格式、公式和隐私规则通过核验。

## 阶段 1：钉钉只读入口试点

1. 由钉钉管理员确认公司已启用开放平台/CLI 访问，并建立测试组织范围。
2. 安装 [DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)，使用 OAuth 登录，不把令牌写入仓库。
3. 先开放只读能力：查日历、文档、会议纪要和网盘文件元数据。
4. 配置用户和群白名单、任务并发限制、附件大小限制。
5. 禁止自动发审批、自动共享文件和自动修改钉钉业务数据。

验收：未授权用户不能触发；日志能关联实际员工；读取范围符合钉钉授权范围。

## 阶段 2：Himice 群机器人

使用钉钉企业机器人 Stream 模式接收群内 `@机器人` 指令。适配器将指令转换为 [Skill Interface v1](interfaces/skill-interface-v1.md)，通过本地 Agent CLI 调用已部署 Skill。

建议首个命令只做低风险流程：

```text
@Himice助手 使用 himice-budget-process
附件：客户报价.xlsx
模板：默认内置模板
```

若需要接收附件，先下载到隔离任务目录；处理完成后默认只返回摘要和本地任务编号。经用户确认后才能把生成文件上传回钉钉。

验收：消息、图片、附件、超时、取消、重复请求和人工确认均有可预测行为；机器人不可越过 Skill 的必填信息和隐私检查。

## 阶段 3：待办与审批

- 使用钉钉官方开放能力创建待办、审批草稿或宜搭表单。
- 创建前展示目标组织、审批模板、人员、字段和附件清单。
- 默认生成草稿；最终提交必须由实际经办人确认。
- 回读钉钉返回的业务 ID 和状态，写入本地任务记录。

验收：无静默提交；重复调用具备幂等键；撤销和失败不产生半完成业务。

## 阶段 4：集中式企业 Agent（条件触发）

只有满足以下任一条件才立项：

- 多部门需要统一入口与版本；
- 长任务需跨设备恢复；
- 公司要求集中审计和成本分摊；
- 知识库必须继承钉钉/网盘/其他源系统权限；
- 每日稳定调用量使单机运行无法维护。

届时再选择一个编排框架、一个企业知识层和一个可观测平台，避免同类组件重复建设。

## 回滚

任何阶段出现权限、数据或稳定性问题时，关闭机器人/应用授权即可回退到阶段 0；现有 Himice Skills 和本地模板不受影响。
