# 架构

## 分层

```text
1. 入口层
   Codex / DSH / Claude Code / 千问办公 / 钉钉群与工作台
                         ↓
2. 身份与渠道适配层
   用户、部门、群、会话、附件、白名单、限流、回传格式
                         ↓
3. Agent 编排层（按需启用）
   任务路由、状态、人工确认、重试、恢复、审批、审计事件
                         ↓
4. Himice Skill 层
   预算 / 备用金 / 操作费用报销 / 会议转录 / 办公与知识能力
                         ↓
5. 工具与数据层
   OfficeCLI / 官方办公 Skills / 本地模板 / MCP / 钉钉开放能力
                         ↓
6. 治理层
   权限、数据分类、日志、评测、成本、版本、留存与删除
```

## 不变原则

1. **业务规则归 Skill。** 渠道机器人和运行时适配器不得复制预算、代付、人补、报销等规则。
2. **平台可替换。** 更换模型、Agent 框架或钉钉连接方式不应修改业务 Skill。
3. **默认本地处理。** 原始报价、发票、税号、录音和生成文件不因接入钉钉而自动上传。
4. **身份向下传递。** 每次调用都携带实际用户、组织、部门、来源群和请求 ID；禁止多人共享模型密钥或机器人身份执行个人业务。
5. **写操作可见。** 写入钉钉、发起审批、共享文件或修改外部系统前必须输出预览并确认。
6. **结果可核验。** 文件类任务返回本地输出路径、使用的 Skill 版本、模板版本、核验结果和待人工确认项。

## 一次任务的数据流

1. 入口接收用户指令和附件，只保存到隔离的本地任务目录。
2. 渠道适配器验证用户/群白名单并生成 `request_id`。
3. 路由器根据 Skill ID 选择 Codex、DSH、Claude Code 或获批的千问运行时。
4. Skill 检查必填信息、敏感等级与授权；缺项时只询问缺项。
5. Skill 调用本地办公工具处理文件，生成预览与核验报告。
6. 产生外部写入时进入人工确认；只读步骤可继续。
7. 返回最小必要摘要。原始文件是否回传钉钉由数据等级和用户确认共同决定。
8. 审计记录保存元数据和结果校验值；默认不记录文件正文、税号、联系方式和模型密钥。

## 从 Skills 到平台

现阶段的三套目录继续独立部署。平台化只增加适配器：

- `codex` 适配器调用 Codex 已部署 Skill。
- `dsh` 适配器调用 `~/.dsh/skills` 中的同名 Skill。
- `claude-code` 适配器显式调用 `/himice-*`。
- `qwen` 适配器只有在企业合同明确允许相应交互或 API 场景后启用。
- `dingtalk` 适配器只负责身份、消息、附件、待办和审批，不改写 Skill 规则。

统一接口见 [interfaces/skill-interface-v1.md](interfaces/skill-interface-v1.md)。
