# 业务硬规则 · 项目预算审批单

这些规则**会被财务追责**，不是操作偏好，因此单独成文，不混进 `pitfalls.md`。

约定：

- 每条标注**来源与日期**，便于追溯；来源不明或仅为推测的，写「**待确认**」而不是当成规则
- **口径变化时以财务最新说法为准**；本文件与财务新说法冲突时，改本文件而不是绕过
- 来源中的具体客户名、人名、金额、账号一律不落库，以角色描述代替
- 「拦截点」列为 `../SKILL.md` 提交前验证清单中的对应动作——**每条硬规则都必须有拦截动作**，不能只躺在本文档里

## 一、取数口径

### R1 三个金额锚点固定取预算表 F64 / F65 / J52

- **规则**：
  - 项目收入预算 = 预算表 `F64`（预计收入总计）
  - 项目成本预算 = 预算表 `F65`（预计成本总计）
  - 项目操作费用金额 = 预算表 `J52`（操作费用**小计**）
- **推论**：**不要**用其他行或别的小计替代；操作费用取的是小计行，不是明细行。
- **来源**：用户明确指定（含单元格位置）
- **日期**：2026-10-23
- **拦截点**：清单「收入预算 = `F64`；成本预算 = `F65`」「操作费用金额 = `J52`」

### R2 行号可能随项目变化，取数前先确认锚点

- **规则**：不同项目的预算表**行数可能不同**，`F64/F65/J52` 并非永远指向同一含义。取数前先核对这三个单元格的**行标签**（预计收入 / 预计成本 / 操作费用小计）是否吻合，不吻合则按标签重新定位。
- **来源**：用户明确提示（「由于每个项目的表格中行数可能不同」）
- **日期**：2026-10-23
- **拦截点**：清单「收入预算/成本预算/操作费用金额」三项——取数阶段前置校验

### R3 毛利与毛利率由表单自动计算，不手工填

- **规则**：填好收入与成本后，毛利与毛利率会**自动跳转**，不要手工输入。
- **推论**：毛利可作为收入、成本是否填对的**反查手段**。
- **来源**：用户明确说明
- **日期**：2026-10-23
- **拦截点**：清单「毛利/毛利率为表单自动计算值，未手工干预」

### R4 金额以预算表所载为准，表格精度差异不追改

- **规则**：预算表金额常为**长小数**（未四舍五入），表单会按自身精度呈现，可能与预算表末位相差几分。**以收入、成本填对为准**，不为末位差回头改表。
- **来源**：用户确认（「小数位这个没关系，只要预计收入和预计成本填对了就可以」）
- **日期**：2026-10-23
- **拦截点**：清单「收入预算 = `F64`；成本预算 = `F65`」

## 二、字段口径

### R5 客户名称填公司全称，不填联系人

- **规则**：客户名称字段填**客户公司全称**。历史表里可能被误填成「公司全称 + 联系人姓名」，须以公司全称为准。
- **来源**：用户纠正（「这里人工做表疏忽，填公司名称」）
- **日期**：2026-10-23
- **拦截点**：清单「客户名称是公司全称（不是联系人姓名）」

### R6 项目负责人默认可覆盖，特殊情况另行说明

- **规则**：项目负责人默认为指定负责人；表单单开时会带入草稿残留值，**必须逐次核对并覆盖**。
- **来源**：用户说明 + 实操验证（草稿残留确实是他人）
- **日期**：2026-10-23
- **拦截点**：清单「项目负责人为本项目实际负责人（已覆盖草稿残留值）」

### R7 项目类型默认「差旅」，特殊情况由发起人说明

- **来源**：用户说明
- **日期**：2026-10-23
- **拦截点**：清单「项目类型正确（默认差旅，特殊已说明）」

### R8 客户渠道费用默认 0

- **规则**：无渠道费用的项目填 `0`；非 0 须发起人说明。
- **来源**：用户说明（「客户渠道费用默认为 0；特殊情况特殊说明」）
- **日期**：2026-10-23
- **拦截点**：清单「客户渠道费用、是否有预收款…按默认与规则填写」

### R9 是否有预收款默认「否」，选否时金额与日期留空

- **规则**：默认「否」，此时预收款金额与预收款日期为**非必填**，填 `0` 或留空均可。
- **来源**：用户说明
- **日期**：2026-10-23
- **拦截点**：清单「客户渠道费用、是否有预收款、预收款金额/日期按默认与规则填写」

### R10 操作公司、部门默认不变

- **规则**：项目操作公司、项目部门按系统默认带出，通常不动；特殊情形须发起人说明。
- **来源**：用户说明（「操作公司默认」「项目部门默认」）
- **日期**：2026-10-23
- **拦截点**：清单「执行地点、操作公司、部门已按默认值或发起人说明确认」

## 三、附件要件

### R11 附件一 = 预算表（合同有则一并），不因缺合同而等待

- **规则**：附件一上传项目预算表；**合同用户给到就上传，没给就只上传预算表**，不得为等合同而卡住流程。
- **来源**：用户明确说明
- **日期**：2026-10-23
- **拦截点**：清单「附件一已含预算表（有合同则一并）」

### R12 附件二 = 预估协作人审批表

- **规则**：模板备注写明「新项目预算发起时请同时上传协作人业绩分配表（预估业绩使用）」，故附件二必传。
- **来源**：模板内备注 + 用户说明
- **日期**：2026-10-23
- **拦截点**：清单「附件二已含预估协作人审批表」

### R13 附件名取文件名本身，不得改名

- **规则**：附件上传取**文件名**而非完整路径。用短路径副本可以，但**必须保留原始文件名**。
- **来源**：实操验证（曾用短名导致附件名不符规范）
- **日期**：2026-10-23
- **拦截点**：清单两项附件——上传后核对附件名

### R14 备注默认无，特殊情况特殊说明

- **来源**：用户说明（「备注无，特殊情况特殊说明」）
- **日期**：2026-10-23
- **拦截点**：提交前人工确认阶段核对备注

## 四、与相邻流程的口径边界

| 口径 | 归属流程 | 说明 |
|---|---|---|
| 借款金额 | **借款单流程** | 取预算表用款申请表 `C25` 现金小计，见兄弟技能；**不要用操作费用小计替代** |
| 付款三大件（发票/合同/结算单） | 付款流程 | 预算审批单**不需要**；本项目预算表属于预算流程材料 |
| 预估协作人审批表 | 预算流程 | 同时是附件二，属性分配与业绩预估 |
| 用印 | 用印流程 | 预算单提交时合同可能尚未盖章，**不强行等待** |

- **来源**：跨流程实操比对
- **日期**：2026-10-23
- **拦截点**：清单「附件一/附件二」两项（含不越界上传其他流程材料）
