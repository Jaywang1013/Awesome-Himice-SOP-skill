# 业务硬规则 · 项目付款

这些规则**会被财务追责**，不是操作偏好，因此单独成文，不混进 `pitfalls.md`。

约定：

- 每条标注**来源与日期**，便于追溯；来源不明或仅为推测的，写「**待确认**」而不是当成规则
- **口径变化时以财务最新说法为准**；本文件与财务新说法冲突时，改本文件而不是绕过
- 来源中的具体客户名、人名、金额、账号一律不落库，以角色描述代替
- 「拦截点」列为 `../SKILL.md` 提交前验证清单中的对应动作——**每条硬规则都必须有拦截动作**，不能只躺在本文档里

---

## 一、凭证与附件要件

### R1 付款三大件 = 发票、合同、结算单

- **规则**：付款流程的凭证只有这三类。**项目预算表属于另一条独立流程**，不算付款附件。
- **推论**：备注里**禁止**出现「项目预算表后补」。
- **来源**：用户口头纠正（Himice 厦门项目人员）
- **日期**：2026-10-22
- **拦截点**：清单「备注只写凭证缺件与必要口径说明，未写『项目预算表后补』」

### R2 附件要件随付款性质变化

| 付款性质 | 要件 |
|---|---|
| 预付款 | **发票 + 合同**（不需要结算单） |
| 尾款 / 结算 | 发票 + 合同 + **结算单** |
| 押金 / 全款 | 按财务当次说明，默认同预付款 |

- **来源**：用户口头说明
- **日期**：2026-10-22
- **拦截点**：清单「附件要件符合本笔付款性质」

### R3 缺件写进备注，不静默提交

- **规则**：三大件缺哪件就写「xx 后补」，不得因为缺件而跳过或自行补齐。
- **来源**：用户口头说明
- **日期**：2026-10-21
- **拦截点**：清单「备注只写凭证缺件与必要口径说明」

## 二、金额

### R4 金额以发票价税合计为准，与合同不一致必须停下确认

- **规则**：合同金额与发票金额不一致时，**停下向发起人确认**，不得静默取其一；确认结果写入备注或快照留痕。
- **来源**：用户明确指令（金额必须人工确认）；2026-10-22 实操中确实出现过报价单金额与发票金额相差数倍的情况
- **日期**：2026-10-21（指令）/ 2026-10-22（实操验证）
- **拦截点**：清单「付款金额与发票价税合计一致；与合同不一致处已确认并留痕」

### R5 大写是金额的校验手段

- **规则**：大写由表单自动生成；**每次填完金额都要用大写反查**，不一致说明金额没真正填对。
- **来源**：操作实测（多次成功复现）
- **日期**：2026-10-21
- **拦截点**：清单「大写金额与付款金额互相印证」

### R6 供应商银行账户优先从电子发票读取

- **规则**：电子发票上通常印有销方开户行与账号，**优先以发票所载为准**，不必另行索要。
- **来源**：操作实测（从发票 PDF 成功摘出完整账户信息）
- **日期**：2026-10-22
- **拦截点**：清单「开户行、账号与合同/发票所载一致」

### R7 收款单位必须与发票开票方一致

- **规则**：收款单位与发票开票方不一致时**优先按发票主体**；若确为关联方代收，须取得发起人明确指示并在备注注明代收关系。
- **来源**：用户实操中给出的收款方与发票开票方不一致，经核对后更正为发票主体
- **日期**：2026-10-22
- **拦截点**：清单「收款单位与发票开票方一致；代收已获明确指示并写入备注」

## 三、时间

### R8 约定付款时间按合同约定日倒推，预留 2 天以上

- **规则**：申请到付款需预留 2 天以上（1 天走审批，付款发生在流程完成次日）。合同写「X 月 X 日前付款」时，约定付款时间最多填到前一日。
- **来源**：用户口头说明（含其付款节奏口径）
- **日期**：2026-10-21
- **拦截点**：清单「约定付款时间已按合同约定日倒推，并预留 2 天以上」

### R9 合同约定的付款期限写进备注

- **规则**：合同/确认书写明付款期限时，备注加上「合同注明 X 月 X 日前完成付款」字样。
- **来源**：用户口头说明
- **日期**：2026-10-21
- **拦截点**：清单「合同约定的付款期限已写入备注」

### R10 合同期限已过时说明顺延原因

- **规则**：合同要求「活动开始前付款」但活动当日已开始、实际无法达成时，按实际可行日填写并在备注写明顺延原因。
- **来源**：用户实操确认（一次真实单件采用此处理）
- **日期**：2026-10-22
- **拦截点**：清单「约定付款时间已按合同约定日倒推，并预留 2 天以上」（顺延说明随备注一并核对）

## 四、字段口径

### R11 成本费用类别 = A 类 + B 类写在同一个框

- **规则**：该字段只有一个输入框，值是「费用性质 + 付款性质」的组合（如「<A类费用>预付款」），**不是两个字段**。
- **来源**：用户口头说明 + 实操验证
- **日期**：2026-10-21（说明）/ 2026-10-22（验证）
- **拦截点**：清单「成本费用类别为 A 类 + B 类组合，且与本次付款性质匹配」

### R12 DC 付款默认「否」

- **来源**：用户口头说明
- **日期**：2026-10-21
- **拦截点**：清单「DC 付款为『否』（除非发起人另有说明）」

### R13 付款通知电话默认取发起人钉钉预留号

- **规则**：默认用发起人在钉钉预留的手机号（个人主页可查），无需每次询问。
- **来源**：用户口头说明
- **日期**：2026-10-22
- **拦截点**：清单「付款通知电话为发起人钉钉预留号」

## 五、抄送

### R14 项目级固定抄送清单

- **规则**：**部分项目要求全流程抄送同一组固定人员**，此类项目发起的每一张审批单都要带上，不能只加一次。
- **实现**：清单写在本机 `field-mapping.local.md` 的「项目固定抄送人」段（**人名不落库**）。
- **来源**：用户口头指定（一次真实项目要求全流程抄送三人）
- **日期**：2026-10-22
- **拦截点**：清单「抄送人完整：含项目要求的固定抄送人（R14）」

### R15 抄送默认不额外加人

- **规则**：除模板自带的默认抄送人外，只有发起人明确要求时才添加，不自行扩大抄送范围。
- **来源**：用户口头说明
- **日期**：2026-10-21
- **拦截点**：清单「抄送人完整：…未擅自扩大抄送范围（R15）」

## 六、与相邻流程的口径边界

| 口径 | 归属流程 | 说明 |
|---|---|---|
| 项目预算表 | 预算流程 | 付款流程**不需要**，也不该写进付款备注 |
| 预估协作人审批表 | 预算流程 | 属性分配与业绩预估，与付款无关 |
| 借款金额 | 借款单流程 | 口径见兄弟技能，**不要用操作费用小计替代** |
| 操作费用小计 | 预算流程 | 与付款金额无换算关系，不可互相替代 |

- **来源**：跨流程实操比对
- **日期**：2026-10-23
- **拦截点**：清单「备注只写凭证缺件与必要口径说明」（含不越界写其他流程材料）
