# 沙盘推演协议（Simulation Protocol）

本文件定义 `himice-tender-simulation` 的多智能体编排细节。执行时按本协议操作，SKILL.md 只负责路由与决策。

## 1. 并行编排方式

在 DSH 中使用并行 subagent 或 workflow 工具：

- **每家公司一个 subagent**，prompt 自包含：给它招标书解析结果 + 公司人设卡 + 输出要求，不共享其他公司的方案。
- 全部公司方案生成后（并行完成），再进入评标阶段。
- 评标阶段由主对话扮演评标委员会（不必再开 subagent，保证评标口径一致）；如需深度答辩，可再并行开一轮"修正 subagent"。

## 2. 公司人设卡（生成模板）

每家竞标公司按以下字段生成人设，写入推演计划：

```
公司名：<按招标类型推断或用户指定>
类型：会展公司 / 公关公司 / 广告公司 / 整合营销 / 其他
规模与实力：大 / 中 / 小，资质亮点
优势：2-3 条（如本地资源、行业案例、低价、技术强）
报价风格：低价冲量 / 均衡 / 高价高质 / 激进让利
过往项目倾向：1-2 条参考
```

对手推断原则：优先用户指定；未指定时按招标所在城市（如厦门）与类型给出 3-4 家合理对手，并标注"推断"。

## 3. 评分计算口径

- 从招标书提取的评分标准转为权重表：`评分项 | 满分 | 权重% | 我方当前得分 | 对手得分`。
- 中标概率估算：按各家加权得分归一化，注明"模型推断，非真实评标"。
- 报价得分按招标书规则计算（如"满足要求最低价得满分，每高 X% 扣 Y 分"）；规则缺失时用通用最低价基准并注明。

## 4. 轮次控制

- 默认 2 轮：第 1 轮各家独立出策略 → 评标；第 2 轮智海王潮按反馈优化 + 一家最强对手按我方策略反击，再评标。
- 每轮结束时输出：排名、得分表、关键评语、我方下一步调整点。
- 用户可要求增加轮次；单轮推演目标控制在对话成本可接受范围。

## 5. 输出收敛

最终报告必须包含：
1. 评分标准速览表
2. 竞标格局对比表（公司 × 策略/报价/优势/弱点）
3. 我方最优方案（技术+商务+加分项）
4. 报价策略（区间、锚点、毛利）
5. 风险清单（废标风险 / 资质缺口 / 需澄清 / 时间）
6. 待确认项清单

## 6. 失败与回退

- 无法提取评分标准 → 停止推演，先请用户提供或确认评分规则。
- subagent 生成失败/超时 → 重试一次；仍失败则该项标注"未生成"，不阻塞整体。
- 估算类输出（中标概率、排名）一律标注"模型推断"。
