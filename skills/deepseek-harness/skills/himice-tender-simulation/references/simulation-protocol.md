# 沙盘推演协议（Simulation Protocol）

本文件定义 `himice-tender-simulation` 的完整推演编排细节。执行时按本协议操作，SKILL.md 只负责路由与决策。协议借鉴群体智能推演（MiroFish/OASIS 式）的核心机制，但全部用 DSH 会话内能力实现。

## 1. 记忆库（Graph & Memory）格式

在会话工作区建立 `tender-sim/<项目名>/` 目录，以下文件为本推演的"图谱与记忆"：

### graph.json（知识图谱）

```json
{
  "nodes": [
    {"id": "org-1", "type": "招标方", "name": "某集团", "summary": "…", "attrs": {}},
    {"id": "bid-1", "type": "竞标公司", "name": "智海王潮", "summary": "…", "attrs": {"报价风格": "均衡"}},
    {"id": "crit-1", "type": "评分项", "name": "技术方案", "summary": "满分40分", "attrs": {"权重": 0.4}}
  ],
  "edges": [
    {"from": "bid-1", "to": "org-1", "type": "投标"},
    {"from": "crit-1", "to": "bid-1", "type": "评分"}
  ]
}
```

- 阶段 0-2 从招标书提取实体写入；阶段 5-8 每轮结果追加。
- 追加遵循"节点幂等、边可新增"：已有节点更新 attrs，不重复建节点。

### personas.json（人设卡）

```json
{
  "companies": [
    {"id": "bid-1", "name": "智海王潮", "实力": "…", "资质亮点": "…", "报价风格": "均衡",
     "策略底线": "毛利≥20%", "核心诉求": "中标+维持品牌", "推断": false}
  ],
  "committee": [
    {"id": "exp-1", "role": "技术专家", "偏好": "方案创新性", "关注点": "执行细节", "易触动": "成功案例"}
  ]
}
```

### environment.json（环境）

```json
{
  "timeline": ["澄清期", "方案准备期", "报价截止", "开标", "评标", "定标"],
  "events": [{"time": "澄清期", "desc": "客户举办澄清会"}],
  "activity": {"bid-1": "积极", "bid-2": "观望"}
}
```

### round-log.jsonl（时序记忆，append-only）

每行一条，记录每轮关键结果：

```json
{"round": 1, "phase": "方案", "bid": "bid-1", "action": "出方案", "detail": "技术方案要点…", "score": null}
{"round": 1, "phase": "评标", "bid": "bid-1", "score": 82, "comment": "方案创新性强，报价偏高"}
```

## 2. 并行编排方式

- **每家公司一个 subagent**：prompt 自包含——给它人设卡（该公司的）+ 招标要点 + 当前环境 + 图谱相关节点，不共享其他公司方案。
- 全部公司并行完成后，主模型统一推进到评标。
- 评标由主模型扮演评标委员会（保证口径一致）；如需深度答辩，可再并行开一轮"修正 subagent"。

### subagent prompt 模板

```
你是<公司名>的投标策略官。公司人设：<persona>。招标要点：<招标书解析>。
当前环境：<environment>。已知对手动态：<已有信息，可空>。
请输出本轮投标策略：1) 技术方案要点(3-5条)；2) 商务承诺；3) 报价金额与理由；
4) 加分项策略；5) 可能的弱点。只按你的立场决策，不要参考其他公司方案。
```

## 3. 评标计算口径

- 评分标准转权重表：`评分项 | 满分 | 权重% | 我方得分 | 对手得分`。
- 中标概率按加权得分归一化，注明"模型推断"。
- 报价得分按招标书规则；缺失时用最低价基准并注明。

## 4. 上帝视角注入（Interview）

主模型在两轮之间执行：

1. **调整我方变量**：改报价/方案 → 重评一轮 → 观察排名变化。
2. **Interview 某公司**：向该公司 subagent（或按其人设模拟）注入一条消息，如"若对手再降5%你怎么办"，记录即时反应到 round-log。
3. **注入外部事件**：在 environment.json 增加事件（预算调整/加急/新竞争对手），观察各家应变。

## 5. 轮次控制

- 默认 2 轮：第 1 轮各家独立出策略 → 评标；第 2 轮智海王潮按反馈优化 + 最强对手反击 → 再评标。
- 每轮结束输出：排名、得分表、关键评语、我方调整点，并**回写 round-log.jsonl 与 graph.json**。
- 用户可要求增加轮次；控制对话成本在可接受范围。

## 6. 报告生成要点

- 报告所有数据从记忆库读取（graph.json / round-log.jsonl），不凭对话印象。
- 分章节：评分速览 → 竞格局对比 → 我方最优方案 → 报价策略 → 风险清单 → 推演回放 → 待确认。
- 防幻觉：不得捏造评分数字、报价或案例；缺失信息标注"待确认"。

## 7. 失败与回退

- 无法提取评分标准 → 停止推演，先请用户提供或确认评分规则。
- subagent 生成失败/超时 → 重试一次；仍失败该项标注"未生成"。
- 估算类输出一律标注"模型推断"。
