# 招投标本体定义（Tender Ontology）

本文件定义 `himice-tender-simulation` 知识图谱的实体与关系类型，供阶段 1（本体定义）与 `graph.json` 使用。固定本体覆盖招投标通用场景；项目特定扩展由一次 LLM 调用补充。

## 1. 实体类型（Entity Types）

| 类型（type） | 说明 | 关键属性（attrs） |
| --- | --- | --- |
| `招标方` | 发布招标的组织 | 名称、行业、预算上限、联系人 |
| `竞标公司` | 参与投标的供应商（含智海王潮） | 实力规模、资质亮点、案例、报价风格、策略底线 |
| `评标专家` | 评标委员会成员 | 角色（技术/商务/报价/甲方）、打分偏好、关注点 |
| `资质项` | 资格要求/资质证书 | 名称、要求等级、我方是否满足 |
| `报价方案` | 某公司某轮的报价与方案 | 报价金额、技术方案要点、商务承诺、加分项 |
| `评分项` | 招标书评分标准条目 | 满分、权重、评分细则 |
| `关键事件` | 投标周期中的事件 | 时间、描述、影响 |
| `联合体`（项目补充） | 多家联合投标（如招标要求） | 成员、牵头方、协议要点 |

> 固定 7 类 + 按项目扩展；类型名用中文保持可读，`type` 字段值固定小写化使用。

## 2. 关系类型（Edge Types）

| 类型（type） | from → to | 说明 |
| --- | --- | --- |
| `投标` | 竞标公司 → 招标方 | 该公司参与本项目投标 |
| `评分` | 评标专家/评分项 → 竞标公司 | 打分关系（可在 attrs 记分值） |
| `竞争` | 竞标公司 → 竞标公司 | 互为竞争对手 |
| `要求` | 招标方 → 资质项/评分项 | 招标方提出的要求 |
| `满足` | 竞标公司 → 资质项 | 该公司满足某资质 |
| `提供` | 竞标公司 → 报价方案 | 该公司提交的方案 |
| `关联` | 任意 → 任意 | 通用弱关系（如公司与案例） |
| `触发` | 关键事件 → 竞标公司 | 事件影响某公司 |

## 3. 项目特定扩展

当招标书含固定本体外的概念时（如"联合体投标""分包要求""绿色资质加分"）：

1. 用一次 LLM 调用生成扩展本体：`{"entity_types": [...], "edge_types": [...]}`，格式同上。
2. 扩展类型追加进 `graph.json` 的本体说明，并遵循"节点幂等、边可新增"。
3. 扩展项在报告中标明来源（招标书条款原文）。

## 4. 图谱写入规则

- 节点：`id` 用语义稳定前缀（`org-`/`bid-`/`exp-`/`qual-`/`offer-`/`crit-`/`evt-`）；同名实体复用已有 id，只更新 attrs。
- 边：引用已有节点 id；同一 (from,to,type) 不重复建边，变化写 attrs（如 `score`）。
- 每轮推演后：报价/方案变更 → 新增 `报价方案` 节点或更新 attrs；评标结果 → 新增/更新 `评分` 边。
