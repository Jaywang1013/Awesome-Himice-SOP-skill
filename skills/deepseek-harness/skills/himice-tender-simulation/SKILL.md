# Himice 招投标沙盘推演（Tender Simulation）

把"各家竞标 + 评标"搬进对话，用**图谱记忆 + 并行多智能体 + 多轮推演 + 上帝视角注入**完整模拟招投标过程，最终给出智海王潮的最优投标方案、报价策略与风险清单。

**机制来源**：本技能借鉴群体智能推演引擎（如 MiroFish / OASIS）的核心思想——种子提取 → 本体 → 图谱 → 人设 → 环境 → 并行模拟 → 变量注入 → 记忆回写 → 报告。全部在 DSH 会话内用现有模型与并行 subagent 实现，**无需安装 MiroFish、OASIS、Zep 或任何外部引擎**。不包含任何上游代码。

## 输入（开始前确认）

- **必填**：招标书/招标公告/采购需求文件（PDF/Word/Excel，先用 `dsh-file-upload` 上传识别，或直接提供路径）。
- **选填**：智海王潮的公司资质、过往案例、可用预算、目标毛利率；已知竞争对手名单；评分标准如有异议处。
- 缺失的关键信息先询问，不得臆造评分标准或资质条件。

## 执行流程（九阶段）

### 阶段 0 · 种子提取（Seed Extraction）

1. 读取招标书全文，按语义块切分（每块约 800 字、重叠 100 字，句边界优先）。
2. 额外收集可选种子：行业背景、客户信息、往届类似项目案例（用户提供或标注"无"）。
3. 输出：分块文本清单 + 全文要点速览。

### 阶段 1 · 本体定义（Ontology）

按招投标领域固定本体 + 项目补充，定义图谱的实体与关系类型（详见 `references/tender-ontology.md`）：

- 实体：招标方、竞标公司、评标专家、资质项、报价方案、评分项、关键事件。
- 关系：投标、评分、竞争、要求、提供、关联等。
- 项目特定补充（如某招标新增"联合体"实体）用一次 LLM 调用扩展，输出追加到本体。

### 阶段 2 · 图谱与记忆库构建（Graph & Memory）

在会话工作区建立结构化记忆库（JSON 文件），作为"图谱"：

```
tender-sim/<项目名>/
├── graph.json          # 节点(nodes) + 边(edges)，随推演增量写入
├── personas.json       # 竞标公司与评标专家人设卡
├── environment.json    # 投标周期、事件、各家活动强度
├── round-log.jsonl     # 每轮推演时序记录（append-only）
└── report.md           # 最终投标策略报告
```

- 从招标书提取实体写入 `graph.json`（招标方、评分项、资质门槛等）。
- 图谱是**活文档**：每一轮推演的结果（报价、方案要点、评标意见）都追加为节点/边，形成可回溯的时序记忆。

### 阶段 3 · 人设生成（Persona Generation）

用 LLM 为每个角色生成人设卡，写入 `personas.json`：

- **竞标公司**（智海王潮 + 3-4 家对手）：实力规模、资质亮点、行业案例倾向、**报价风格**（低价冲量/均衡/高价高质/激进让利）、**策略底线**（可接受毛利下限）、核心诉求。
- **评标委员会**（5 人）：技术专家×2、商务专家×1、报价评审×1、甲方代表×1——各自打分偏好、关注点、易被触动的点。
- 人设基于招标书信息与推断生成；推断项标注"推断"。

### 阶段 4 · 环境配置（Environment）

用 LLM 生成投标周期环境，写入 `environment.json`：

- 时间线：澄清期 → 方案准备期 → 报价截止 → 开标 → 评标 → 定标。
- 关键事件：澄清会、答疑、竞争对手动作（如压低报价传闻）。
- 各家活动强度：谁积极、谁观望、谁可能放弃。

### 阶段 5 · 并行模拟（Parallel Simulation）—— 核心

**每家公司一个独立 subagent**，输入人设卡 + 环境 + 图谱当前状态，各自独立生成本轮策略（互不串供）。主模型充当"世界"推进轮次：

- 第 1 轮：各家出技术方案要点 + 商务承诺 + 报价 + 加分项策略。
- 评标：主模型扮演评标委员会按评分标准逐项打分、写评语。
- 每轮结束：结果写入 `round-log.jsonl`，关键节点/边追加进 `graph.json`。

### 阶段 6 · 上帝视角注入（God View Injection）

主模型在两轮之间以"上帝视角"注入变量并观察反应：

- 调整智海王潮报价/方案，看排名变化；
- 向任意公司"采访"（interview）：注入一条消息（如"如果对手再降 5% 你会怎么办"），观察其即时反应；
- 注入外部事件（如客户加急、预算调整），看各家应变。

### 阶段 7 · 时序记忆回写（Memory Rollback）

每轮推演后把结果结构化回写：报价变化、方案调整、评语、排名。形成**可回溯的时序记忆**——报告阶段与后续推演都可引用，不依赖一次性对话上下文。

### 阶段 8 · 迭代优化（至少 1 轮）

针对智海王潮低分项与对手强项，调整方案与报价，重跑一轮；观察报价敏感度。

### 阶段 9 · 报告生成（Report）

参照 `references/tender-rules.md`，用记忆库数据生成结构化投标策略报告（`report.md`）：
1. 招标关键要求与评分标准速览（表格）
2. 竞标格局：各家人设、策略、报价、优劣势对比表
3. **智海王潮最优投标方案**：技术方案要点、商务承诺、加分项
4. **报价策略**：建议报价区间、锚点理由、毛利测算（结合 `himice-budget-process` 核验）
5. 风险清单：废标风险、资质缺口、需澄清项、时间风险
6. 推演过程回放：各轮报价/排名变化（引用 round-log）
7. 待确认项：需要用户提供但缺失的信息

## 与仓库其他技能配合

- 招标书文件读取：`dsh-file-upload`（MarkItDown 转 Markdown）或 `dsh-univer-office` 读 Excel 评分表。
- 报价与预算核验：`himice-budget-process`（供应商成本 → 预算表 → 毛利）。
- 投标方案 PPT：`pptfast`（原生可编辑 PPTX）。
- 会议纪要/录音：`himice-vibevoice`（澄清会、答疑会录音转写）。

## 边界与安全

- 模拟结果仅供决策参考，**不是真实评标保证**；估算的中标概率是模型推断，不构成承诺。
- 招标书、报价、资质等未公开资料只在本地处理，不发送到未授权服务。
- 不臆造公司资质、业绩或报价依据；缺失信息标注"待确认"。
- 竞标对手信息均为推断，不得作为真实情报使用或传播。
