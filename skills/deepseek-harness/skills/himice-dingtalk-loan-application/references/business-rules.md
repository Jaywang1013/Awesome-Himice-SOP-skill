# 业务硬规则 · 项目借款单

这些规则**会被财务追责**，不是操作偏好，因此单独成文，不混进 `pitfalls.md`。

约定：

- 每条标注**来源与日期**，便于追溯；来源不明或仅为推测的，写「**待确认**」而不是当成规则
- **口径变化时以财务最新说法为准**；本文件与财务新说法冲突时，改本文件而不是绕过
- 来源中的具体客户名、人名、金额、账号一律不落库，以角色描述代替
- 「拦截点」列为 `../SKILL.md` 提交前验证清单中的对应动作——**每条硬规则都必须有拦截动作**，不能只躺在本文档里

---

## 一、金额口径（最高风险项）

### R1 借款金额 = 用款申请表 `C25`（现金小计）

- **规则**：借款金额取自项目预算表**用款申请表**的 **`C25`（现金）小计**。
- **为什么**：用款申请表把用款拆成 `已转帐 / 待转帐 / 刷卡 / 现金` 几档。**待转帐走对公付款；现金支出无法转账，才需要先借备用金**。所以借款只对应「现金」那一档。
- **自校验**：`C21 小计 = C23 待转帐 + C24 刷卡 + C25 现金 + …`，各档之和应等于小计。
- **来源**：用户明确指定单元格；档位逻辑经预算表实测核对
- **日期**：2026-10-23
- **拦截点**：清单「借款金额 = 用款申请表 `C25`（现金小计）」

### R2 不得用操作费用小计或其他金额替代借款金额

- **规则**：操作费用小计属于**预算审批单**的口径，与借款金额**没有换算关系**，不可互相替代。
- **来源**：跨流程口径比对（两者数值明显不同，曾确认口径边界）
- **日期**：2026-10-23
- **拦截点**：清单「借款金额**未**误用操作费用小计或其他口径」

### R3 大写是金额的校验手段

- **规则**：大写由表单自动生成；**每次填完金额都要用大写反查**，不一致说明金额没真正填对。
- **来源**：操作实测（多次成功复现）
- **日期**：2026-10-23
- **拦截点**：清单「借款金额 = …；**已用大写反查**」

### R4 取数前先确认工作表名与行标签

- **规则**：用款申请表的**工作表名可能带尾随空格**，用脚本读取须原样匹配；`C25` 所在行的标签应确为「现金」，不吻合则按标签重新定位。
- **来源**：实操验证（曾因尾随空格报 `KeyError`）
- **日期**：2026-10-23
- **拦截点**：取数阶段前置校验

## 二、收款信息（高隐私、高风险）

### R5 收款人与银行账户必须由发起人当次明确提供

- **规则**：收款人姓名、银行账号、开户行**一律由发起人明确提供**；**不得**沿用历史单值、不得从其他文件推测、不得猜测。
- **推论**：账号须**逐位核对**（位数、易混数字）。
- **来源**：用户明确要求（提供了两组收款账户供选择，并指定本次使用哪一个）
- **日期**：2026-10-23
- **拦截点**：清单「收款人姓名与发起人指定一致」「收款人银行账号、开户行与发起人提供一致（逐位核对）」

### R6 收款账户信息不落仓库

- **规则**：银行账号、开户行等个人/供应商账户信息**只存本机** `field-mapping.local.md`（已被 `.gitignore` 覆盖），**不进仓库、不写进技能文档**。
- **来源**：团队隐私规范
- **日期**：2026-10-23
- **拦截点**：提交前隐私自查（仓库层面由 `validate.sh --privacy` 把关）

## 三、字段口径

### R7 借款申请人必须是发起人

- **规则**：字段名即写明「必须是发起人」，系统自动带出；若不是本人，停下核对，不要强行改。
- **来源**：模板字段约束
- **日期**：2026-10-23
- **拦截点**：清单「借款申请人…与默认值一致」

### R8 所属公司、核算部门默认不变

- **规则**：按系统默认带出，通常不动；特殊情形须发起人说明。
- **来源**：用户说明（「借款申请人默认」「所属公司默认」「核酸部门默认」——「核酸」为「核算」笔误）
- **日期**：2026-10-23
- **拦截点**：清单「借款申请人、所属公司、核算部门与默认值一致」

### R9 项目负责人经人员选择器指定

- **规则**：项目负责人取项目归属负责人；表单的人员选择器**默认视图是组织架构树**，须用顶部搜索框按姓名检索。
- **来源**：用户说明 + 实操验证
- **日期**：2026-10-23
- **拦截点**：清单「项目负责人为本项目实际负责人」

### R10 项目名称用完整鱼鹰号串

- **规则**：项目名称（鱼鹰号）填完整串 `（城市）编号 项目全称`，与预算表一致。
- **来源**：用户说明（「项目名称同预算表中的项目名称」）
- **日期**：2026-10-23
- **拦截点**：清单「项目名称（鱼鹰号）与预算表一致」

## 四、附件

### R11 附件（借款明细）= 项目预算表

- **规则**：该模板的附件位只有一个，上传**项目预算表**。
- **来源**：用户说明（「附件附项目预算表」）
- **日期**：2026-10-23
- **拦截点**：清单「附件（借款明细）已上传项目预算表，且附件名正确」

### R12 附件名取文件名本身，不得改名

- **规则**：附件上传取**文件名**而非完整路径。短路径副本可以，但**必须保留原始文件名**。
- **来源**：实操验证
- **日期**：2026-10-23
- **拦截点**：清单「附件（借款明细）…附件名正确」

## 五、模板辨识（相邻模板会填错表）

### R13 选定前核对模板全名

- **规则**：「项目借款单（厦门）」「非项目采购借款」「借款申请」名称相近、**横向并排**出现在搜索结果中，**字段结构完全不同**。点错会填错整张表。
- **处置**：立即关闭标签页重开，**不要在错模板上继续填**。
- **来源**：实操踩坑（曾点错到非项目采购借款，字段完全不同）
- **日期**：2026-10-23
- **拦截点**：清单「模板确为『项目借款单（厦门）』」

## 六、与相邻流程的口径边界

| 口径 | 归属流程 | 说明 |
|---|---|---|
| 项目收入 / 成本 / 操作费用小计 | 预算审批单流程 | 借款单**不需要**，也不该填进本单 |
| 预估协作人审批表 | 预算流程 | 预算审批单的附件二，**与借款单无关** |
| 付款三大件（发票/合同/结算单） | 付款流程 | **与借款单无关** |
| 用印 | 用印流程 | 借款单不涉及用印 |

- **来源**：跨流程口径比对
- **日期**：2026-10-23
- **拦截点**：清单「借款金额未误用操作费用小计或其他口径」
