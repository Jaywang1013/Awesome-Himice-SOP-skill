# 本机默认值模板 · 用印申请

> **配对约定**：本目录下 `field-mapping.md` 与 `field-mapping.local.md` 是**一对**——
> `field-mapping.md` 放**结构**（字段名、必填、控件类型、取值来源），入库共享；
> `field-mapping.local.md` 放**本机实际值**（公司全称、部门、项目别名表），只存本机、不入库。
>
> **用法**：把本文件复制为同目录下的 `field-mapping.local.md`，按本机实际情况补全。
> `.local.md` 已被仓库 `.gitignore`（`*.local.md`）覆盖，**不会进仓库**；本 `example` 文件只含占位符，可入库。
>
> 这里放的是"每次都要填、但基本不变"的值，以及**含客户信息的对照表**。
> 凡涉及客户名、项目编号、人名，一律只写在本文件。

## 二、⚠️ 不设默认项（重要）

以下三项**在本文件中不写默认值**，也不得由执行方自行取值——它们必须**当场向用户确认**：

| 字段 | 为什么不设默认 |
|---|---|
| 文件管控分类（字段 6） | 由**用户口头告知**三选一（对客销售合同 / 投标文件 / 对供应商采购），执行方不自行判断；分类决定合规路径与归档方式 |
| 电子印章 / 实体章（字段 12） | **仅当跨公司使用集团（海口）印章选「是」时**必须当场问用户；集团有独立规定，选错要重新走流程 |
| 是否需要原件（字段 13） | 同上，跨公司场景必须当场问；涉及是否邮寄合同原件到集团法务归档 |

> **放默认值会直接诱发事故**：把这三项写成"默认值"，执行方会照填而不问，导致选错印章类型或漏走跨公司流程。
> 非跨公司场景下，字段 12/13 才适用上表的 `实体章` / `否`，且**仍需在提交前清单中核对**。

## 三、鱼鹰号别名表

用于把口头简称匹配到完整项目串（格式：`（城市）编号 项目全称`）。

| 常用简称 | 完整鱼鹰号 | 备注 |
|---|---|---|
| `<简称A>` | `（<城市>）<编号><项目全称>` | 客户：`<客户简称>` |
| `<简称B>` | `（<城市>）<编号><项目全称>` | 客户：`<客户简称>` |

**匹配优先级**：精确编号 → 全称包含 → 简称包含 → 人工兜底。
**多义时回问用户，不猜。**

> 注意：用印表单里**没有独立的"项目"字段**，鱼鹰号与项目名称是拼进「用印文件名称」的（见 `field-mapping.md` 字段 7）。
> 本表的作用是：用户只给简称时，据此还原完整串。
