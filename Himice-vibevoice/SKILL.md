# Himice VibeVoice

使用 [VibeVoice-ASR](https://github.com/microsoft/VibeVoice) 的语音转文字能力处理会议音频。它支持长音频、说话人、时间戳和自定义热词。本 Skill 只提供 Himice 的工作流和术语；不包含 VibeVoice 源代码或模型权重。安装、模型、版本与 MIT 许可证以 [上游仓库](https://github.com/microsoft/VibeVoice) 为准。

## 开始前收集

先确认录音已获参会者和客户授权，并收集：会议/活动名称、客户或主办方、日期和地点、参会角色或名单、语言/方言、预期输出、需重点校对的名称与术语。缺少授权或原始音频时，不进行转写。

读取 [会议与厦门术语词表](references/meeting-glossary.md)，把本项目实际的客户名、人员名、供应商名、场地名、品牌名和缩写追加为热词。热词用于提高识别，不可据此臆造音频未出现的内容。

## 转写与整理

1. 使用上游 ASR 的文件推理或已获批准的内部部署，生成原始转写，保留说话人和时间戳；超过单段支持长度时按自然议题边界切分，并保留连续时间基准。
2. 将转写与音频对照校验姓名、数字、金额、日期、地点、合同/项目编号和责任人。听不清或证据不足的内容标为 `[待确认]`，不得猜测或悄悄改写。
3. 输出时将“原始转写”和“整理后纪要”分开。纪要至少包含：会议背景、关键结论、决定事项、行动项、风险/待确认项。
4. 行动项用表格列出“事项、负责人、截止时间、来源时间戳、状态”；音频未给出负责人或日期时填 `[待确认]`。
5. 用项目名称、日期、语言、版本和“AI 辅助转写，已/未人工复核”标识交付物。对外发布、合同金额、承诺、法律/安全内容必须人工复核后才可使用。

## 会展场景重点

- 识别并区分会前策划、搭建、彩排、开展、现场执行、撤场、复盘等阶段；不要把讨论方案当成已确认执行项。
- 重点核对会场/分会场、舞美、灯光、音响、视频、导视、签到、嘉宾接待、展商、赞助、物料、供应商、预算、合同、发票、结算和代付相关内容。
- Himice 公开业务语境包括会议展览、产业会展/节庆、整合营销、奖励旅游、城市品牌活动和文旅项目；公司内部项目事实仍以本次会议资料为准。

## 隐私与质量

- 仅处理已授权录音，并按公司资料分级和客户约定保存、访问和删除；不要将原始录音或转写扩散给无权限人员。
- 转写可能含错字、漏字、错分说话人或错误时间戳。不得把 AI 输出视为会议纪要的最终依据，尤其是金额、交期、责任与承诺。
- 不使用该 Skill 合成、克隆、伪造或冒充任何人的声音。
